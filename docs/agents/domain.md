# Domain docs

## Layout

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root.
- Architecture decision records in `docs/adr/`.

## Before exploring

Read `GLOSSARY.md` and ADRs relevant to the area being explored.

If these files are absent, proceed silently. The domain-modeling
skill creates them when terms or decisions are resolved.

## Vocabulary

Use glossary terms when naming domain concepts in issues, code,
tests, and proposals.

When a needed concept is missing, check whether an existing term
fits; otherwise note the gap for domain-modeling.

## Decision conflicts

If a proposal contradicts an ADR, identify that ADR and explain
why the decision should be reopened.
