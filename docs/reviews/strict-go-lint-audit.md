## Findings and responsibility routing

All findings initially have **pending** status. References are stable across file
movement. Owners must preserve the ID, record concrete commits and validation,
and state a reason for any partial resolution or accepted exception.

### AUD-001 — Logical blocks and declarations run together

Evidence: `client.go` places Config, Client and callSettings beside one another
without separation; several call-option functions are adjacent; ordinary
validation/initialization/return phases across library and tests lack logical
spacing. This makes ownership and failure transitions harder to scan.

Route: [#15](https://github.com/aadidenko/typesafe-sdk-go/issues/15) for client,
reliability and focused tests; [#16](https://github.com/aadidenko/typesafe-sdk-go/issues/16)
for Questions/Answers/Assets and focused tests; [#17](https://github.com/aadidenko/typesafe-sdk-go/issues/17)
for shared scenarios/examples. Apply mechanical changes separately. Validate the
full formatting pipeline twice, read-only fmt-check, and review grouping in
context; whitespace checks cannot judge every logical relationship.

### AUD-002 — Client and reliability functions combine distinct phases

Evidence: `NewClient` mixes authentication, URL/default validation, timeout,
retry/header/logging snapshots and final construction; `SystemOne` mixes Question
validation, request assembly, transport and response validation; `do` and
`retryable` collect several deadline/eligibility decisions.

Route: **#15**. Extract coherent responsibilities with explicit data flow.
Preserve per-call settings, total/attempt cancellation, stop/cancel ownership,
joined causes, retained metadata and once-only encoded bytes. This is a
behavior-preserving refactor, not a confirmed runtime fix. Validate existing
client/configuration/ownership/retry/logging tests on Go 1.25 with race detection,
plus complete profile and metrics. Do not add private-helper tests.

### AUD-003 — Parsing and multipart assembly obscure invariants

Evidence: `parseSystemOne` interleaves root/usage checks, answer dispatch and
requested-name checks. `parseScoreAnswer` combines legend shape/index/content,
score/range and distribution checks. `validateAnsweredQuestions` embeds both
Choice and Score comparison. `prepareAssets` combines descriptors, JSON assembly
and multipart writing.

Route: **#16**. Separate these responsibilities while retaining protocol field
paths, nullable Box Confidence, requested-answer semantics, unknown raw data and
single prepared representation. Validate mixed Questions, malformed successes,
image sources/snapshots, multipart descriptors, decoding/extensions and complete
workflow/replay tests. Changes to acceptance rules would require separate work.

### AUD-004 — Combined scenarios and examples need readable phases

Evidence: `TestCompleteWorkflow`, `TestConcurrentCompleteRequestsRemainIsolated`,
`TestCompressedJSONAndMultipartRetriesReplayExactBytes` and the complete example's
`run` each combine setup, request construction, wire checks and result assertions.
Nested fixture branches make it hard to see which checks establish each guarantee.

Route: **#17**. Keep complete public-client workflows and visible chronology;
name helpers after coherent setup, decoding or assertion responsibilities.
Retain the first failed attempt before mutation and replay, exact compressed
byte equality, constructor snapshots and once-only marshaller counts. Handler
helpers must return errors or nonfatally report and return. Validate the same
combined paths and concurrent distinct request inputs under Go 1.25 race checks;
compile all examples and live source without invoking provider code.

### AUD-005 — Unchecked operations weaken error intent and fixture failures

Evidence: `prepareAssets` assigns a JSON marshal error to `_`; `doAttempt`
discards Body.Close's result; many focused tests discard NewClient, decode,
read/write, multipart and cleanup errors or use unchecked type assertions.
Examples discard output errors and some type assertions. For example,
`TestExplicitConfigurationIgnoresEnvironmentAndClonesHeaders` ignores Decode,
`TestImageSnapshotsAndDistinctNamedUploads` ignores NextPart, and
`examples/extensions` asserts UnknownAnswer without checking.

Route: **#15** owns configuration/client/models/retry/logging/ownership tests and
`compression.go`; **#16** owns Questions/Answers/Assets/decoding/extensions and
focused tests; **#17** owns `compression_test.go`, shared workflow fixtures and
examples. Report meaningful errors, check assertions and stop dependent fixture
work after failure. Handle unreachable failures deliberately; do not invent
runtime branches or turn successful evaluation into failed cleanup. Validate
existing public HTTP scenarios, selected strict error checks and each actual
local exception. New runtime fixes, if confirmed, need a targeted public-seam
regression and their own commit.

### AUD-006 — A handler calls a fatal test operation

Evidence: `choice_score_test.go:TestMixedNoulChoiceScore` calls `t.Fatal(err)`
inside the httptest HandlerFunc when request decoding fails. That handler runs
outside the test goroutine; fatal failure is invalid there.

Route: **#16**. Use nonfatal reporting with explicit return, or an error-returning
fixture helper handled by the handler. Retain the original real-client mixed
Question test. Validate its normal path, inspect every handler/helper call site,
and run the configured checks. This fixes test failure handling; it does not
justify a claim that the SDK's runtime response behavior changed.

### AUD-007 — Public declarations lack standalone documentation

Evidence: Client, NewClient, SystemOne, WithModel, WithHeaders, WithTimeouts,
Version, sentinel/constant groups, typed accessors and several Kind methods
lack their own explanatory comments. Package/README coverage does not make
those individual Godoc entries self-contained.

Route: **#15** for client/reliability declarations; **#16** for Answer/accessor
entries. Describe observable semantics and meaningful cleanup/concurrency/input
requirements without restating every parameter. Keep domain names and exported
signatures. Validate exported-documentation checks and manually read the result.

### AUD-008 — Positional literals hide field roles

Evidence: long Client/callSettings construction, positional ProtocolError and
ValidationError values, anonymous wire structs and wide adjacent-string test
rows require readers to cross-reference declaration order. This is particularly
fragile when fields have the same type or a test table spans many lines.

Route: **#15** for construction/error metadata and focused tables; **#16** for
wire/validation structs and Question/Answer test tables; **#17** for combined
scenario/example data. Prefer keyed literals where they communicate meaning.
Small obvious tuples or standard geometry values may remain when a concrete
readability judgement favors them. Preserve JSON tags and values; validate wire
and protocol metadata through the existing public tests. This recommendation
is not a demand to rewrite every small literal mechanically.

## Reviewed deviations and non-applicability

| ID | Evidence and reason |
| --- | --- |
| D-001 | Public names such as SystemOne, Noul and Box, module/package naming, Config and functional CallOption signatures are established ADR 0002 contracts. No renaming, typed handle or option-interface redesign is authorized for style. |
| D-002 | A network response is fully consumed before closure. A Close error after complete valid bytes must not replace successful evaluation or the actual HTTP/read failure. Preserve ownership; inspect the error or justify the exact local suppression. No blanket Close exclusion is acceptable. |
| D-003 | Returned response maps/slices and typed Answer maps are caller-owned mutable values, not private client state. AnswersByKind creates a new outer map; its nested values need not become deep immutable copies. Assets.Add mutates the caller's request map; its atomic reference counter does not promise concurrent mutation safety for that map. Caller mutation during construction/encoding is excluded by documentation. |
| D-004 | Caller custom JSON marshalers, image encoding and compression run synchronously. Compression checks the total context before work and before transport but cannot interrupt CPU encoding midway; initial request preparation precedes the transport budget. This is documented behavior, not a new end-to-end CPU deadline promise. |
| D-005 | Optional diagnostics intentionally report attempt/retry/call categories before returning typed errors. Apply Uber's single-handling advice with the accepted logging contract in mind. Raw causes/field paths are excluded from automatic logs; caller-requested body logs and returned raw metadata are explicit sensitive-data access, not automatic sanitization guarantees. |
| D-006 | HTTPMetadata embedding exposes retained public metadata and DecodeResponse by design. Removing embedding to adopt Uber's public-struct preference would change the public API. Record such redesign as separate work if proposed; it is not fixed here and is not required by this audit. |
| D-007 | Google precedence retains ordinary MixedCaps unexported globals rather than Uber's underscore prefix. The standard library's typed sync/atomic is sufficient; an Uber atomic dependency is unnecessary. A zero Compression value deliberately selects defaults; do not apply enum-start advice by changing values. |
| D-008 | No fixed width is imposed. Long literal JSON fixtures may remain when keeping contract data together helps review; dense multi-responsibility expressions still require judgement. Numerical function thresholds are the explicit repository rule. |
| D-009 | Caller-selected image paths are useful SDK input, not a server-controlled filesystem path. Retry jitter and deterministic random compression data do not generate keys or security tokens. These uses may justify exact local gosec exceptions after checking the actual finding and bounds. |
| D-010 | Go examples are commands and may exit in main. Early-exit/defer interactions still need contextual review, especially complete/models custom transports and local httptest servers. Library code must never call fatal logging or os.Exit. |
| D-011 | Protobuf/gRPC naming, cgo/system APIs, complex CLI frameworks, streaming and generated-code rules have no corresponding source here. There is no SDK background worker requiring a new shutdown API or third-party leak dependency. No new abstraction or package split is justified solely by package file count. |

Recommendations that would change public signatures, metadata embedding,
response mutability, request ownership, time-budget definitions or accepted wire
semantics require a separate proposal/issue. No such change is required to
resolve the eight actionable findings, and none is claimed implemented here.

## Local suppression review plan

The baseline contains **no nolint annotations**. The following categories identify
likely contextual decisions; they do not preapprove future annotations. Each
final annotation must name its actual analyzer, explain the exact site's intent
or safety, remain local and be checked for use by nolintlint.

| Site/category | Required substantive review |
| --- | --- |
| Network Body.Close after a read; gzip/multipart/fixture cleanup | Distinguish a completed read from a failed read/write/finalization. Preserve the actual evaluation/error result. Do not suppress finalization errors that can invalidate outgoing bytes. |
| `ImageFromFile` | Path is intentionally selected by the caller. Do not silently restrict path semantics to satisfy a scanner. Errors should continue to exclude the path value. |
| Retry random jitter and random fixture payload | Confirm randomness is only backoff distribution or deterministic test data, never credential generation. |
| Bounded fixture int-to-byte conversions | Check the actual loop/range and arithmetic prove representability; avoid a blanket integer-conversion exemption. |
| Example terminal output/stderr failure reporting | Check print errors or explain why the exact final diagnostic cannot meaningfully report its own write failure. Do not exempt all fmt/logging calls. |
| Synthetic keys and named secret markers in tests | Verify each value is fabricated and used by a specific assertion, rather than a real credential or broad test-file exclusion. |
| Any new exception | Document its concrete invariant, affected behavior and validation. A nonempty explanation alone is insufficient. |
